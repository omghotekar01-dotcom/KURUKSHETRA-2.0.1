# 3-Minute Judge Demo

## 0:00–0:25 — Problem

“Autonomous agents can read email, databases, repositories, MCP tools and payment systems. Prompt filters inspect text; TrustKernel controls what the agent is actually allowed to do.”

## 0:25–0:45 — Architecture

Show the pipeline:

`Identity → Intent → Action Graph → Provenance/Taint → Policy → Repair/Approval/Block → Evidence`

Emphasize that the enforcement happens before the real tool call.

## 0:45–1:35 — Red-team scenario

Run **Judge Mode**. Pause on the prompt-injection case:

- untrusted email enters agent context
- agent reaches for `.env`
- secret label propagates into external email
- TrustKernel reconstructs the causal chain
- decision: BLOCK
- incident + audit evidence are produced

Then show the poisoned MCP-tool case being blocked.

## 1:35–2:05 — Safe Plan Repair

Show destructive SQL:

`database.drop(sales)` → policy violation → `database.select(sales)` → REWRITE

Explain that the system protects task completion, not only rejection.

## 2:05–2:30 — Human approval

Show ₹95,000 payment crossing the ₹50,000 automatic limit and becoming `REQUIRE_APPROVAL`.

## 2:30–2:50 — Benign control

Run safe analytics and show it is allowed/audited. This demonstrates that TrustKernel is not a “block everything” firewall.

## 2:50–3:00 — Close

“TrustKernel is IAM + runtime authorization + forensic evidence for autonomous agents. The same boundary can protect coding, finance, support and MCP-based enterprise agents.”

## Demo rule

Never claim a metric that was not actually generated by the current build. The deterministic benchmark is a regression suite, not a claim of universal attack prevention.
